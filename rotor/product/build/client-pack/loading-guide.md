# Loading guide: Rotor Sheet and Rotor Core into your team's AI tools

For Brandon to send, and for the person at [COMPANY] who looks after IT and AI tools. Use after the CEO has signed off the Rotor Sheet. Replace bracketed text.

**What this guide covers.** How to load two files into the AI tool your beta team already uses, so the AI works from them in every chat:
1. **The Rotor Sheet:** your signed-off strategy, written in your own words. Dated version: [SHEET VERSION AND DATE].
2. **The Rotor Core:** licensed material from Brandon. It is the file Brandon sends, kept apart from the Sheet. This guide does not describe what is in it. Do not edit it, copy it into other documents or share it outside the team's project.

**Time.** 30 to 60 minutes for the person loading. Brandon then checks the setup and finalises the two notes below (about 45 minutes of his time).

## Loading it: one project per team
Set up one shared project, assistant or agent for the beta team. Menu names change often, so check the current names on your platform before you start. The pattern is the same everywhere.

| Platform | The project's instructions go in | The Sheet and the Core go in | Each team member gets |
|---|---|---|---|
| Claude | A Project's instructions | Project knowledge (two files) | Access to the shared Project; a new chat per task |
| ChatGPT | A custom GPT's, or a Project's, instructions | The GPT's or Project's knowledge files (two files) | A link to the GPT or Project |
| Microsoft Copilot | An agent's instructions | The agent's knowledge sources (two files) | Access to the agent |
| Google Gemini | A Gem's instructions | Files attached to the Gem (two files) | A link to the shared Gem |
| Any other assistant | Pasted as the first message of each new chat | Pasted straight after it, or attached | The texts, by email |

Steps, in every case:
1. Create the shared project, assistant or agent. Name it plainly, for example "[COMPANY] team assistant".
2. Paste the instruction text Brandon sent into the instructions field.
3. Add the two files as knowledge. Keep them as two separate files with their own names and dates.
4. Check the sharing: only the beta team's members can open it. Admins who must check the setup can read it, under your confidentiality terms.
5. Check the settings: [training on this account's content is switched off in its settings]. Take a screenshot of the setting and send it to Brandon.
6. Run one test chat. Ask the project: "What is our main effort, and what is one guardrail?" The answer should match the Sheet. Send Brandon a screenshot, not the chat contents.
7. Tell Brandon it is done. He checks that the project is set up as agreed and runs the red-team on the team lead's ten dilemmas in week 5.

## Updating the Sheet later
When the CEO approves a new version of the Sheet, replace the old Sheet file with the new one, keep the date in the file name, and keep the old version somewhere safe, not in the project. Never keep two versions in the project at the same time.

### Template 2: Plain-language behaviour summary

> **How the team AI behaves**
>
> The AI in this project is set up to:
> - **Ask questions rather than give instructions.** It helps you think. It does not tell you what to do.
> - **Assume you know more about your situation than it does.** You have the context. It does not.
> - **Raise issues in proportion to the stakes.** Most of the time it just answers. When a choice touches the strategy, it asks one light question. When a choice clearly crosses an agreed guardrail, it says so plainly.
> - **Accept your decision once you have made it.** It does not argue it again.
> - **Never steer you covertly.** If it has a concern, it says so openly.
>
> You can always override it.
